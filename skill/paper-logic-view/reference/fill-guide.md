# 填写说明：怎么把一篇论文填成 logic.json

你要做的只有一件事：读论文，写一份符合 `schema/logic.schema.json` 的 JSON。不写 HTML、CSS、JS。

## 一、先读全文，再动手

1. 用 `scripts/pdf_text.py 论文.pdf -o 论文.txt` 抽出按页分好的文字。页码以这份文字里的"=== 第 N 页 ==="为准，它就是 PDF 的物理页码。
2. 通读一遍，先用一句话写出 `summary`：这篇论文想让读者相信什么，靠什么让人相信。
3. 找主线：核心问题（problem）→ 核心方法（method）→ 主要结论（claim）→ 撑结论的关键实验（evidence）。这几条标重要度 3。
4. 再补中间环节（重要度 2），最后才考虑次要的（重要度 1）。**宁少勿滥**：不推动论证的句子不要标，让它被调暗，空转规则才有意义。

篇幅参考：8 页的论文 30–60 条标注；20 页的论文 50–100 条。

## 二、quote 怎么引

- **逐字复制**抽出来的原文，一句或半句，12–200 个字符最合适。
- 不改写、不翻译、不补标点、不纠错别字。原文写错了也照抄。
- **不要引公式**。句子里有公式时，只引公式前面或后面的文字部分。
- 不要用省略号拼接两段原文。需要两段，就拆成两条标注。
- 太短、太常见的句子（如 "as shown in Table 2"）容易定位到别处，选一个能唯一确定位置的片段。
- 跨行、跨栏、跨页都没关系，模板会处理连字符断行（`predic-` + `tion`）和连字（ﬁ）。引的时候把断行的单词拼回去写成 `prediction` 即可，写成 `predic- tion` 也能找到。
- 图表本身不能引。要引用图表的结论，就引正文里描述它的那句话，或者图注里的一句。

## 三、连线怎么连

方向一律是 **from = 理由，to = 被撑的话**。问自己："因为 from，所以 to"读得通吗？

- 读得通，而且中间不用补话 → `supports`。
- 读得通，但要补一句作者没写的话才通 → `indirect`，把要补的那句写进 `missing_step`。这就是"跳帧"。
- from 回答了 to 提出的问题或承诺 → `answers`（to 必须是 problem）。
- from 给 to 加了条件或边界 → `qualifies`。
- from 和 to 说法矛盾 → `conflicts`，在 `note` 里写哪里打架。

**结论没有人撑，就不要硬连。** 让它挂着，页面会把它列成"坑没填"，这正是用户想看到的。不要为了让页面好看去编连线。

## 四、B 档判断（有就标，没有就不标）

- **说过头**：在"证据 → 结论"那条连线上加 `overreach`，写清楚"证据只覆盖 X，结论说的是 Y"。例：`"只在 2 个数据集上测试，结论写的是'对各类场景普遍有效'"`。
- **替代解释**：在"证据 → 结论"那条连线上加 `alternative`，写"这个提升也可能来自……，作者没排除"。
- **隐含前提**：推理要成立，得先默认一件论文没写的事。新增一条标注：
  ```json
  {"id":"h1","type":"assumption","implicit":true,"importance":2,
   "text":"默认训练集和测试集来自同一分布","anchor":"a12"}
  ```
  再用 `supports` 从 h1 连到用到它的那条结论。`anchor` 填它要挂在旁边显示的标注 id。
- **前后打架**：`conflicts` 连线，见上。
- **先用后定义**：给 definition 标注加 `first_used_page`，写这个术语第一次出现的页码。

## 五、external：靠论文外部撑的

结论是靠引用别人的工作撑的（"已有研究表明……[12]"），写 `"external": "引用 [12]"`。这样它不算"坑没填"，但会单列在"只靠引用"里，提醒读者这一环在论文外面。

## 六、查自己的草稿（mode: write）

- `mode` 填 `"write"`。
- 标注照常标，但**判断要比读别人的论文更严**：作者心里知道、纸面上没写出来的推理，一律算缺。
- `note` 可以直接写读者读到这里会问什么，比如"读者会问：为什么是 7 天？"。

## 七、写完以后

```bash
python3 scripts/check_logic.py 论文.pdf logic.json
```

- 有 ✗ 的条目必须改：引用找不到、id 重复、连线指向不存在的标注、indirect 没写 missing_step……
- ~ 是近似定位：一般是你的引用和原文差了几个字，最好改成逐字一致。
- 全部通过后再打包：

```bash
python3 scripts/pack_logic.py 论文.pdf logic.json -o 论文_逻辑图.html
```

## 八、常见错误

| 错误 | 改法 |
|---|---|
| 把每句话都标上 | 只标推动论证的；不标的会被调暗，这是功能 |
| 箭头方向反了（结论 → 证据） | from 是理由，to 是结论 |
| 引用里带公式或省略号 | 只引文字；两段就拆成两条 |
| page 写成论文印的页码 | 用 pdf_text.py 输出里的物理页码 |
| 为了不报"坑没填"硬连一条 | 没有就是没有，让它报出来 |
| indirect 的 missing_step 写"缺少论证" | 写出缺的那句话本身，比如"缺：为什么误差下降说明模型学到了周期性" |
