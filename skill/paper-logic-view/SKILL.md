# paper-logic-view：把论文的论证逻辑画在 PDF 原文上

你只做一件事：**读论文，填一份 JSON**。高亮、箭头、调暗、问题清单、交互、深浅色、手机适配，全部由固定模板 `templates/viewer.html` 完成。不要写 HTML、CSS、JS，也不要改模板。

这个 skill 不依赖任何特定的模型或 agent：判断（挑句子、定类型、连箭头）由你自己的模型做，脚本只用 Python 标准库，不调任何 API。

## 文件

| 文件 | 干什么 |
|---|---|
| `reference/tags.md` | 8 种标签、5 种连线、重要度、全部检查规则、颜色。**先读这个。** |
| `reference/fill-guide.md` | 填写说明：怎么挑句子、怎么逐字引用、怎么连线、B 档判断怎么写、常见错误。**再读这个。** |
| `schema/logic.schema.json` | 数据格式（JSON Schema） |
| `examples/mini.json` | 小例子：一段编的"共享单车需求预测"草稿 |
| `scripts/pdf_text.py` | 按页抽出 PDF 文字，页码就是要填的 `page` |
| `scripts/check_logic.py` | 校验：结构、id、连线、**引用能不能在 PDF 里找到**，并预算检查规则 |
| `scripts/pack_logic.py` | 把 PDF 和 JSON 装进模板，打包成单个 HTML |
| `templates/viewer.html` | 固定的页面模板 |

## 步骤

1. **确认输入和用法。** 要一个 PDF。用户没说用法时：是用户自己写的稿子就用 `write`，别人的论文就用 `read`。
2. **抽文字。**
   ```bash
   python3 scripts/pdf_text.py 论文.pdf -o 论文.txt
   ```
   读 `论文.txt`。页码以"=== 第 N 页 ==="为准。参考文献之后的内容（附录）一般不标，除非用户要。
3. **读 `reference/tags.md` 和 `reference/fill-guide.md`，然后填 `logic.json`。**
   - 先写 `summary`，再找主线（重要度 3），再补中间环节。
   - `quote` 从 `论文.txt` 里**逐字复制**，不改写、不翻译、不引公式。
   - 没有人撑的结论**不要硬连**。让它挂着，页面会报"坑没填"，这正是用户要看的。
   - B 档（说过头、隐含前提、替代解释、前后打架、先用后定义）有把握才标，每条写清楚具体在哪。
4. **校验，改到通过。**
   ```bash
   python3 scripts/check_logic.py 论文.pdf logic.json
   ```
   有 ✗ 就改：多半是引用和原文差了字，回 `论文.txt` 重新复制。~ 近似定位的也尽量改成逐字一致。
5. **打包。**
   ```bash
   python3 scripts/pack_logic.py 论文.pdf logic.json -o 论文_逻辑图.html
   ```
   PDF 太大（打包后超过 16 MB）会被拒绝，请用户先压缩 PDF。
6. **交给用户。** 告诉用户：
   - 文件在哪，双击就能打开（需要联网加载 cdnjs 上的 PDF.js）；
   - 一句话主线（你的 `summary`）；
   - 校验脚本列出的问题数，挑最重要的 3–5 条用一句话说（"第 X 页那句结论没有任何证据撑"）。空转要打开页面才算，提醒用户看问题清单；
   - 如果是 `write` 用法，最后加一句：判断来自模型，最好在另一个模型里也跑一遍对照。

## 硬规矩

- 只填 JSON，不写页面，不改模板。
- `quote` 必须逐字来自 PDF，校验通过才打包。实在定位不上的，页面会列在"没定位上"里，**不要删掉不报**。
- 不为了页面好看编连线、编证据。
- 不调用任何付费接口，不上传用户的论文。用户的未发表稿件只在本机处理。
- 发布到网上（比如 claude.ai artifact）之前先问用户。打包出来的 HTML 只从 cdnjs 加载 PDF.js，可以直接发布。

## 和别的工具的分工

这个 skill 只回答"论证长什么样、哪里断了"。论文对不对、实验够不够、该怎么改，交给审稿类工具（比如 paper-review）。用户要改稿意见时，告诉他可以拿这里列出的断点去问审稿工具。
